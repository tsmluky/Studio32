# Reportes de avance · Studio32

Para qué: que cualquiera del equipo (sobre todo quien no estuvo en la sesión) sepa
**qué se hizo, qué significa y qué está listo**, sin malentendidos. Nació de un lío
real: un compañero no sabía que ciertas cosas ya estaban hechas.

Cómo funciona:
- **`ESTADO.md`** → la foto SIEMPRE actual: qué está hecho y probado, qué está en
  curso, qué queda. Si tienes 1 minuto, lee esto. Es la fuente de la verdad.
- **`AAAA-MM-DD.md`** → un reporte por día/sesión de trabajo. El histórico, el ritmo.
  Escrito en lenguaje llano, para personas, no técnico.

Reglas:
- Lenguaje de negocio, no de código. "El agente ahora reconoce el miedo del
  paciente", no "franjas_por_dia".
- Cada avance dice el **qué** y el **por qué importa**.
- Vive en el repo (se sincroniza por git). Cuando haya que ENVIARLO a alguien, se
  exporta a PDF o página; el Markdown es el original.
